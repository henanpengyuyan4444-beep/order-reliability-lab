## 核心验收矩阵（必须本人现场做）

| 项目 | 对应测试/入口 | 过关证据 |
|---|---|---|
| 同键同参 32 个并发请求 | TestConcurrentIdempotency | 1 个订单、1 个任务、相同 ID；解释数据库约束和事务 |
| 同键异参 | TestKeyConflict | 409 且无额外任务；解释为什么 request_id 不能当幂等键 |
| 受理后响应丢失 | TestCommittedTimeoutReconcilesWithoutResubmit | unknown → 查询成功，effect=1、POST=1；现场找出查单分支 |
| 创建后重启、受理后进程退出 | TestRestartPending / TestCrashAfterProviderCommit | 重开同一数据库收敛，不换业务号；解释两处事务边界 |
| 旧结果与重复消息 | TestStaleAndDuplicateMessagesCannotRegressTerminal | version 拒绝旧 attempt，终态不回退；说明未覆盖真实 webhook |
| 结果永久未知 | TestRetryBudgetKeepsAmbiguousOutcome | needs_review；不能宣称失败或“全局只执行一次” |
| 请求 ID 排查 | JSON 日志 + demo.ps1 | 从 req_* 找到 order_id、attempt、错误原因，不查看原始敏感内容 |
| Go 并发 | TestBoundedWorkerPoolAndCancellation + race | 解释 goroutine 生命周期、取消、有限并发与数据库串行 |
| 陌生变式 | 下列随机抽题 | 30 分钟内加一个有效失败测试和最小修复，说明剩余风险 |

## 模拟面试 100 分

项目与来源 15；订单正确性 30；Go/数据库 20；排查与现场修改 20；真实 AI/harness 10；表达、业务和学习能力 5。

关键项具有否决性：把超时等同失败、无依据承诺 exactly-once、说不清本人贡献、跳过验证盲信 AI、把敏感数据直接发送给未授权模型。即使总分高，也要补考关键项。

陌生题抽一项：下游查询返回 200 但金额错了；租约缩到 HTTP 超时以下；最后一次尝试中退出；给订单增加货币字段并将其纳入幂等指纹；按配置限制重试次数且拒绝非法配置；给某类可恢复错误增加 jitter 并验证范围。练习时可以看文档，正式验收不能照抄本仓库的已有补丁。

每次记录：日期、题目、能否独立、耗时、失败证据、修复 commit、复测结果。助手替你运行成功只能记到“软件验证”，不能填入“本人通过”。

顺序说明：上表 0–4 是学习和面试训练路线，不是禁止投递的关卡；项目可用并选定原全栈简历后，投递准备可立即并行。
