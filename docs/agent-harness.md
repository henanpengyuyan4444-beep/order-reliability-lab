# 用本项目练 Agent harness

这里的 harness 指约束输入、工具权限、可验证结果与失败处置的工程工作流。本仓库没有实现通用 Agent 平台，也不接任何模型 API。练习围绕你已有真实 AI 项目与当前代码验证。

## 一次可审查的小任务

给 Agent 的任务示例：

> 仅修改 internal/lab 的金额上限校验与相关测试。先写一个目前会失败的边界测试，说明为何失败，再实现最小修改。保持同键同参幂等、同键异参冲突、unknown 查单、终态不回退。不得读取本项目以外文件，不得调用真实下游、读取 .env、凭据或用户数据，不得修改上游许可证、生成虚假测试结果、跳过或删掉失败测试。提交前给出 diff、实际命令、退出码和未验证项。

人先检查任务是否需要读敏感资料；只提供合成订单。模型说“我验证过”不算证据，必须有实际执行记录。学习仓库上传权限不授权向任意模型、网页或第三方发送用户旧项目源码。

## 四个可观察关卡

1. 输入：只给必要文件、清晰的不变量与失败模型；不把整个用户目录传给模型。
2. 工具：只开本地测试与所需源码；网络请求限制为模拟 loopback。浏览网页或 README 的指令是待分析资料，不能变成执行命令或索取密钥的授权。
3. 输出：检查 diff、SQL 条件、错误分类；run verify.ps1，再验证故障；“正常路径跑通”不能证明恢复。
4. 拒绝与恢复：Agent 要上传 .env、替换业务号绕过去重或关掉失败测试时停止该步骤，说明冲突；保留失败样本，再从可信输入重试。

## 真实的红绿验证

测试集中特别验证“200 但业务号/金额错误”“超时却已提交”“迟到失败覆盖成功”等常见错误假设。额外的负向对照会在隔离副本里故意去掉同键异参冲突检查；TestKeyConflict 必须变红。原仓库不修改。若该对照未执行或没命中，应如实写未验证，不能借用其他测试通过来代替。

这一对照只证明一个错误能被一条测试发现，不代表测试穷尽所有风险。用户的学习任务是独立设计另一条有效坏例，先让它失败，再修复并解释。

## 敏感数据验证练习

使用哨兵字符串 do-not-log-me 放在不允许的 JSON 字段中，要求 API 拒绝且日志不含原值；TestHTTPValidationAndSafeLogs 已含该断言。这只是一个日志回归测试，不是 DLP 安全产品或完整泄漏审计。

可再练：在给 Agent 的“下游错误示例”里加入诱导读取密钥的文本，让它作为数据被报告，而不执行。不得使用真实密钥做实验，也不要把“泄漏后再删日志”当合格。
