# 面试准备与可说范围

## 先给真实定位

现在可说：“我选择 goqite 作为开源学习基础，AI 协助补了本地模拟订单实验室；我正在独立阅读和复现故障。现有 AI 应用经历是另一个真实项目。”

完成本人修改与现场验收后才能补充：“我独立改了 X，先用 Y 用例复现失败，再通过 Z 验证；我能解释幂等、未知结果和恢复边界。”把 X/Y/Z 替换成真实 commit 和证据。

不能说：完整交易系统从零原创、已有生产资金经验、上游是我写的、已掌握没有读懂的 AI 代码、通过测试就能保证面试通过。

## 2 分钟项目讲解骨架

问题（重复和丢响应）→ 上游选择（小型队列）→ 两个关键事务 → unknown 查单 → version 防迟到覆盖 → 亲自修改的一项 → 未覆盖的风险。没有亲自修改时直说仍在学习，不伪造案例。

## 追问题与回答抓手

| 问题 | 回答必须包含 |
|---|---|
| 为什么请求 ID 不能当幂等键？ | 每次请求可有不同追踪 ID；业务去重键跨重试稳定，同键必须同业务含义 |
| 唯一索引就够了吗？ | 还要比较输入、正确返回旧单、原子入队；并发跨进程需另验 |
| 提交成功但客户端没收到怎么办？ | 本地重试原幂等键；外部结果未知时按原业务号查询，不靠超时认定失败 |
| 为什么把 unknown 写在发请求前？ | 进程可能在外部成功、本地写回前退出；恢复者不能假定没发过 |
| 既然有队列，为什么不是 exactly-once？ | 任务可重复投递，副作用跨系统；依赖下游持久幂等与可靠查单 |
| 租约过期代表旧任务结束吗？ | 不代表；本地 version 拦迟到更新，下游仍要防重复作用 |
| 一直查不清怎么处理？ | 有限预算后 needs_review，保存 ID/证据；本项目未做复核后台和自动对账 |
| 事务范围为什么不包含 HTTP？ | 跨系统无法原子回滚，长锁还会阻塞；持久状态和恢复协议承接不确定性 |
| 为什么 Go 并发了 DB 还只用一个连接？ | SQLite 写事务串行适合小实验；HTTP 并发仍存在；吞吐目标必须另测 |
| 200 为什么不能直接成功？ | 验业务号、金额、状态、回执与响应格式；返回成功状态不代表语义正确 |
| 怎么验证 AI 的代码？ | 先固定约束和不变量，红绿测试、race、diff 与故障演示；本人能解释每个新增分支 |
| 你最担心哪三项没做？ | 生产鉴权、真实提供方合同/对账、存储与容灾；说明哪项先补及为何 |

## 真实 AI 项目案例模板

上下文与本人职责；一次 Agent/模型输出出错的具体例子；如何观察到错误；怎样缩小输入与权限；修改前后证据；成本或效果有数据才写；敏感资料如何脱敏/本地保留；还不能保证什么。

优先用你真实做过的身份打通、任务状态、异常恢复或 AI 应用工作，具体细节以你的真实经历为准。这里不生成虚构业务指标或假设你负责过某段实现。

## 业务入门边界

先能画出申请提交、提供方受理、业务确认、清算/对账的大致阶段，解释不同产品与渠道细则可能不同，不能把 HTTP 成功当最终业务完成。当前 amount_minor 与 effect 是纯技术模拟，并未实现基金份额或交易规则。后续阅读真实业务资料时核对来源和适用版本，不凭本项目推断真实资金行为。

## 60 分钟模拟流程

5 分钟真实经历与来源；15 分钟项目追问；10 分钟故障排查；20 分钟现场修改与验证；10 分钟 Go/SQL、AI 边界与反问。记录“独立完成/提示后/助手代做”，不是只记对错。具体模拟评分见 learning-plan；投递准备可与学习并行。
